# Existing-component intent connection — 2026-10-04

Stage 2 bounded development design, directly derived from the User's protocol and Stage 1 interface evidence. No new intelligence architecture and no independent plan-acceptance claim.

Request → existing caller-owned context/recovery → existing URI reasoning gateway → validated interpretation → at most five individually presented questions → revision-bound Intent Audit → Accept/Correct → task package → existing executor discovery/selection. Every output remains preparation-only. No execution dispatcher is reachable from this slice.

Model chooses ambiguity, reasoning level and question wording. Runtime enforces ownership, schemas, question ceilings, duplicate-round protection and acceptance revision. Corrections preserve request, context, answers and count; invalidate acceptance/package. Accept confirms meaning, never assumptions as facts or execution permissions. Executor change preserves accepted audit. Unavailable reasoning is reported, never replaced with keyword recipes.

Core context, RAR, ARN.1, graph and optional grounded-memory/bridge collaborators are reused read-only in the opt-in composition. RAR output is a proposal; source references remain separate because RARQuery does not contain provenance. Native session continuation is unsupported in this slice and never claimed.

UI: reuse the approved inline decision-block structure (`docs/design_library/approved/clarification_card_2026-09-27.md`) within existing Workspace harness panel; no new screen/navigation or console. Expose objective, context/provenance, scope, constraints, assumptions, expected outcome, checks and uncertainty; Accept/Correct, then executor selection and an explicit unavailable execution state.
