# Dynamic Planning Slice 1 independent audit

Date: 2026-09-28. Checkout: detached HEAD. Verdict: **REPAIR REQUIRED; not accepted for release**.

Scope: the untracked `DYNAMIC_PLANNING_STAGE2_CANONICAL_PLAN.md`, Stage 1 review and evidence in `docs/research/`, new `uri_v1/execution/planning/`, six new tests, fixture workbooks/battery, and qualification script. No Slice 2 or production integration was audited as completed. This audit changed no source, test, fixture, frozen, or governance status file.

## Findings

1. **Governance and architecture gate.** Stage 2 still says `DRAFT, PLANNING ONLY`; its required accepted architecture file and Stage 3 migration plan do not exist. The active milestone record still names M36 and the machine state contains no Dynamic Planning authorization. Stage 2 decisions D1 to D3, battery/hash freeze, protected-file manifest, and rollback base are not recorded as settled. Slice 1 cannot be released on these records. The existing `tests/test_m37_edge_resolution.py::test_edge_and_execution_import_boundaries` also fails because `planning/bindings.py` imports `uri_v1.memory.sources`; the Stage 2 design explicitly calls for this reuse, while the M37 boundary forbids it. Reconcile this boundary in an accepted plan rather than silently changing the test or production interface.
2. **Unresolved work can compile as complete.** `compiler.compile()` rejects `cannot[]` only when `nodes` is empty. With the valid two-workbook fixture plus a `cannot` item and the fixture's two source IDs, it returns `CompiledPlan`. The runner can then report `COMPLETED` for a task whose proposal explicitly declared an unresolved remainder. Slice 1 must reject this as no completion or carry an approved partial state; the latter belongs to Slice 2.
3. **Live contract revalidation is incomplete.** `runner.py` checks only action identity/version lookup and the `qualification` string before dispatching fixed action branches. A changed effect, approval, mechanism, port contract, or verifier coverage with the same qualification string is accepted. The planned capability snapshot and per-node authority revalidation are therefore not established. `actions.py` also hard-codes qualification labels; no record ID plus actual qualification SHA is checked against an approved handler declaration.
4. **Verification does not establish failed-execution exclusion.** `lineage.record_and_verify()` records `claimed_failed`, but `verify.make_memory_verifier()` does not reject a failed claim or nonzero exit code before evaluating output bytes. The runner adds a safety flag on capability change and timeout, but not every caught action, binding, or unexpected failure. This leaves a path for a failed execution with an independently reproducible earlier report to receive `VERIFIED`. A direct adversarial regression is required before acceptance.
5. **Qualification coverage and counters are overstated.** The script executes 12 probes and reports G1/G3/G4/G5 as passed, but omits many mandatory cases in those gates (including failed-node handle, stale source hash, wrong literal, deletion, post-verification change, provider failure, ceilings, and output tampering). It does not run G2 or G8. Its six safety counters start at zero and increment only in selected failed assertions; they are not derived from a complete observed run/event ledger, and denominators per counter are absent. The `qualification_cases.json` fixture hash is `42FE56A98FF8EACFE4CBA8F1A06ED345D1AE2730C201682354D278CF8619F4E2`, but no pre-run frozen manifest was found.
6. **Source hashes are optional at compile time.** `compile(..., candidates=None)` accepts source references and records an empty source hash; `bind_sources()` then fingerprints whatever the registry currently finds. That path does not pin `(source_id, content_sha256)` from the trusted candidate list at compile time. `bind_sources()` also accepts an optional candidate map independent of the plan. It must enforce the plan's pinned hashes and refuse missing hashes.
7. **Other observed boundaries.** The four actions contain no business-domain planning, numeric calculation, fuzzy/latest/first-match source fallback, `uri_core` import, or experimental import. Compiler port edges and repeated inspect/select instances are real. The oracle separately walks `plan.json` and rereads workbook structures without calling the runner or binder, although it shares the existing workbook reader. These positive observations do not close findings 1 to 6.
