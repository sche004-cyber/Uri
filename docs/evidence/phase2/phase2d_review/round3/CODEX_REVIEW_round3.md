## C. New defects and risk assessment

The new evidence-model check has an uncaught fixture input type error. A signed fixture record built from evidence containing `"models": 42` raises `TypeError` at composition because `list(ev["models"])` assumes an iterable. My fresh synthetic probe reproduced this. A client profile started with `--allow-fixture-qualification` could fail startup rather than report `INVALIDATED`; it does **not** run a task. Native records do not take that branch. This is a low-severity robustness defect for a test-only opt-in path and does not block acceptance of the bounded native composition slice. The fixture check is also conditional on the `models` key, while the revised architecture says fixture evidence must name its models (`PHASE2D_COMPOSITION.md:147`); existing test fixtures omit it. A same-client signer could therefore name extra fixture models without model-specific fixture evidence. This is confined to explicit fixture opt-in, but the documentation should state the actual test-mode limit or the validator should enforce the stated rule.
