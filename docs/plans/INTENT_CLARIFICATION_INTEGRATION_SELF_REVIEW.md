Date: 4 October 2026. This is Codex reviewing its own plan, NOT an independent audit. Prepared after the formal plan. Disposition: DRAFT_FOR_USER_DECISION_WITH_EXPLICIT_LIMITATIONS. No implementation/test/model result is claimed.

Reviewed artifact: [formal plan](INTENT_CLARIFICATION_INTEGRATION_PLAN.md), grounded in the accepted scope and pinned actual implementation. Its reuse direction is consistent with model-centric reasoning and execution-disabled preparation. The following concerns must not disappear behind passing structural tests.

| Priority | Risk or unresolved assumption | Required handling / missing evidence |
|---|---|---|
| P1 | BindingService is process-local; restart cannot preserve its authoritative round by restoring a JSON flag. A new round can repeat a reference question or reset service-local safeguards. | Plan deliberately revalidates/reissues rather than modifies frozen persistence. Preserve controller issuance count and carry cumulative cost/no-progress evidence in its existing checkpoint; enforce remaining budget at the composition boundary. Test restart with an answered attribute and confirmed selection. Report continuity limitations rather than claiming seamless recovery. |
| P1 | MemoryAdapter response wrappers do not expose every BindingService provenance/locator argument. Directly calling BindingService to supply them can bypass raw-input admission. | Establish and test one source-specific composition: use public adapter grounding/registration and fresh retrieval; where required provenance cannot be safely supplied through supported interfaces, abstain. Never monkey-patch the frozen adapter or downgrade provenance_required. This limitation can block qualification of that reference class. |
| P1 | Stable field IDs and source spans cannot prove semantic completeness or two differently named fields refer to the same question. Models may omit a prohibition or downgrade its apparent importance initially. | Require source-visible review, pending conflict/manifest review and regression cases for renamed fields, negation and hidden authority assumptions. Measure failures explicitly. No claim that Core fills arbitrary missing meaning or that the plan guarantees reliability. |
| P1 | Fact Manager immediately supersedes changed values, and its evidence helper defaults toward VERIFIED. Importing a model candidate through that path would corrupt established meaning. | Keep pending candidates in the existing cycle; call update_fact only after explicit structured/reviewed selection, with explicit safe status/basis and cycle isolation. Never use update_evidence_fact or Fact.verify for model/user approval claims. Inspect accepted package values against displayed candidates. |
| P1 | Incremental wire shape is specified conceptually, but full JSON-schema fixtures and audit/delta consistency checks are not written or exercised. | First implementation step must encode the exact existing-envelope extension and negative fixtures before merge behavior. | P1 | Checkpoint atomic_write plus RLock is not a multiprocess transaction. Idempotency, early invalidation and crash recovery are planned additions, not current guarantees. | Restrict candidate to one backend process/worker. Test retries, crash points, stale accepts and concurrent submissions through actual routes. Multiworker support and production dispatch atomicity remain outside scope. |
| P2 | The actual external Context Bridge deployment has not been located in the inspected checkout. Its existing adapter hardcodes claims C1–C7. | Fresh/stale fixtures establish branch behavior only. Record deployment path, source schema and claim coverage before enabling a real bridge. Without them, real bridge qualification stays NOT TESTED; do not silently claim all components were combined. |
| P2 | Candidate-specific API/hash changes require Flutter changes; existing production/UI role assignments are not superseded merely by Codex planning authority. | User must confirm the isolated UI implementer. Verify all accepted meaning is visibly rendered, not only carried in hidden JSON. Hash consistency alone does not establish that the user saw or understood the interpretation. |
| P2 | A 36-call cap may not cover repeated reference retrieval or human correction sequences. The selected model's semantic performance is unproven under the revised payload. | Separate inference authorization, exact route selection and reserve human turns. Count every generation, stop at cap and mark incomplete cases NOT TESTED. No automatic fallback, retry loop or model preference recommendation. |
