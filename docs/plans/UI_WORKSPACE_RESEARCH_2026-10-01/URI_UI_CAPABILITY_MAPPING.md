## Classification and truth rules

**Operational** requires current deployment evidence through the canonical desktop path. **Implemented but not connected** means the component exists but its intended desktop/Flutter seam is absent. **Experimental** identifies a research/adapter route whose qualification does not establish production behavior. **Planned** is a proposed interface/capability with no verified implementation. **Blocked** means an existing path cannot currently satisfy acceptance or a concrete dependency is missing.

At this snapshot, no feature receives a fresh desktop Operational claim: health was offline and GUI testing unavailable. Several URI Core capabilities have implemented, historically qualified canonical paths; the rejected desktop middleware blocks calling that deployment operational. “Blocked” here describes product connectivity, not changing a development milestone to BLOCKED or substituting a quota-exhausted model.

Store implementation, qualification, integration and availability as separate axes. Installation and authentication are further distinct axes. A single green enabled badge cannot represent them all.

## Proposed read models (D)

These are field requirements for a future accepted additive projection, **not existing endpoint names**. Prefer extending current authenticated catalogue/turn models over creating a parallel runtime.

| Projection | Minimum fields | Security/accuracy rule |
|---|---|---|
| Capability presentation | opaque id, kind (`tool/skill/specialist/harness`), title, description, task classes, implementation state, integration state, availability/reason/observed_at, source/version, permissions/effects, qualification evidence + scope/date | Server derives effective availability from registry, policy and runtime; UI has no promotion authority |
| Memory record | opaque record/source ids, kind, scope, provenance, authority classification, verification/freshness, access state, correction link | Only authorized readable records; M36 history is a candidate, not a binding or permission |
| Artifact | artifact/run/task ids, filename/media type, version/hash/size, downloadable ref, producer, verification scope/state, provenance, candidate/written-back state | No raw local path or file access outside authenticated FileStore/workspace grants |
| Usage observation | metric, value or null, unit, confidence, source, interval, sample count, coverage, provider/run attribution | Missing cost stays unavailable; subscription fee is separate from marginal task cost |
| Improvement proposal | proposal/version ids, evidence refs, observed pattern + sample/interval, suggested change, expected benefit with assumptions, risks, qualification needed, approval class, lifecycle/status | History cannot authorize execution; no auto-enable or automatic security-policy changes |

Vocabulary: **Abilities** is the catalogue; **Connections** links services; **Models** powers reasoning; **Specialists** are qualified for bounded tasks; **Execution services** are external harnesses; **Skills** are reusable procedures. Details show technical names only on demand.
