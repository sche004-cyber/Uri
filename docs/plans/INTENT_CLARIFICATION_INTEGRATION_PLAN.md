## 3. Minimum changes and state ownership

Affected code: `experimental/intent_workflow/{controller,context,routes}.py`, `scripts/run_intent_workflow_candidate.py`, `uri_ui/lib/widgets/intent_preparation.dart`, and its existing client only if transport signatures require it. Extend `tests/test_intent_workflow.py` and `uri_ui/test/intent_preparation_test.dart`; reuse existing RAR/BindingService/ARN/Fact tests unchanged. No new service or schema registry.

Controller checkpoint version 2 adds only cycle-scoped fields: stable field IDs and source-turn links, pending semantic candidates/conflicts, effective user restriction entries, serialized existing Fact/Session projection, per-reference ARN state, reference-round receipts, request-id receipts and review hash. Existing `request/answers/corrections` remain the source history; no parallel event journal/database. Production SessionManager is not a second durable copy. Use existing atomic_write for this single JSON checkpoint.

**Turn processing:** under the existing controller lock, authenticate owner, verify revision and payload-bound request_id; append the entire answer/correction, increment revision, invalidate acceptance/package eligibility/executor, and durably save PROCESSING before inference. Same request_id/same payload returns its recorded result; a different payload using that ID fails. Single-process, single-worker candidate only; no claim of cross-process transactional safety. Hold/recheck the existing lock/revision for completion; a crash leaves a recoverable unaccepted checkpoint. Failed reasoning retains prior audit/answers and pending question for review; it cannot restore acceptance.

**Reference turns:** use process-local BindingService instances isolated by owner and cycle. Checkpoint existing round IDs, displayed contract, explicit selections and result fingerprints as receipts, not a competing binding implementation. On restart, never deserialize a cached CONFIRMED flag into fresh authority: invalidate open rounds, re-retrieve sources and use existing builder/admission/register paths. Confirmed historical selections can anchor a fresh query only after source/fingerprint validation. A still-ambiguous selection requires a newly displayed round; report that extra interaction. Preserve controller issuance count and cumulative reference cost/no-progress receipts through restart, enforce remaining budget at the composition boundary, and supply applicable prior answered axes through the existing builder rather than resetting them. No persistence modification of frozen BindingService. Reference Change uses its supported tentative/change lifecycle; terminal confirmed references require a new reviewed query/round, not an unsupported `open_change` call.

**ARN persistence:** store `ARNState.to_dict()` in the cycle checkpoint. A strict composition-local decoder reconstructs its existing dataclasses/enums; malformed/incompatible state fails closed rather than clearing cost/eliminations. This is serialization glue, not new recovery logic. Task-goal changes archive the old case; require explicit reviewed scope change before opening a new case. Do not classify every arbitrary answer as an ARN clue.

**Semantic turns:** no domain regex or hard-coded administrative handlers. Core binds only a complete declared typed/control response; otherwise the same Main Brain proposes a delta against stable fields, prior audit, full source history and restrictions. Initial discovery proposes fields with source-turn links; Core mints IDs. Source membership proves provenance, not negation semantics. A natural-language answer creates a visible provisional candidate; unrelated established facts remain unchanged. Only explicitly named correction targets can be proposed for replacement; conflicts stay blocking. Replanning uses the same gateway and retains the restriction set.

The bounded wire addition is inside `intent`: `fields` (initial proposal only: label, JSON scalar type, source turn/span, value or unresolved marker) and `updates` (continuation: Core field ID, answer/correction/uncertain kind, proposed value, source turn/span). `clarification` additionally identifies target field IDs. Full existing audit fields remain mandatory as a proposed review projection; controller rejects changes outside the declared updates instead of silently replacing the audit. Unknown targets/keys/types fail closed. Before coding the merge, add exact schema fixtures and rejection examples to the existing protocol tests; these are part of this seam, not a replacement Model–Runtime Contract.

Original and subsequent user instructions remain verbatim available. Parsed restriction entries have stable IDs/source links; model output cannot omit/remove them from review/package. Restriction withdrawal requires explicit user review of old and new meaning, then a revised audit and fresh final acceptance. Every new user turn already invalidates acceptance. Structural retention cannot detect every prohibition that initial discovery failed to identify; surface source text and qualify that model-dependent gap rather than claiming a deterministic semantic guarantee.

## 4. Acceptance and package integrity

Core computes a versioned canonical hash over the exact review object consumed by Flutter: objective, deliverable, facts/candidates, scope, restrictions, assumptions, uncertainty and provenance. Use explicit UTF-8/sorted-key serialization with no duplicate keys, invalid numbers or implicit coercions. Flutter displays that object, including pending changes and restrictions, and sends its revision/hash on Accept. No client or model computes authoritative state.

Acceptance rejects unresolved required fields, conflicts, pending withdrawal, unprocessed turns, stale reference evidence, failure states or hash mismatch. Optional assumptions remain explicit PROVISIONAL entries; user scope corrections can remove a blocking requirement only through a revised review, never a hidden model downgrade. Freeze package from the same reviewed object, retaining source history and review hash. Review selection promotes a candidate only to accepted user meaning, not VERIFIED world/institutional authority.

`choose()` records executor choice separately in the existing cycle, never mutating the accepted package/hash. Available external harnesses remain selectable, but preparation does not call their run endpoints. Any subsequent user answer/correction invalidates current acceptance and selection before interpretation. No dispatch-envelope service or new approval gate is needed while execution is disabled. Future production handoff is outside this milestone.
