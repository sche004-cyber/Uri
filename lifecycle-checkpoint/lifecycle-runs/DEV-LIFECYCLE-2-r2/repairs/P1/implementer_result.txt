I repaired R1-01. After a Windows worker or gate that wasn't contained, `precheck()` now reports `contained=False` instead of `True`. Nothing is committed.

**Acceptance criteria:**
- After a worker or gate that ran without a job (job not created, or not assigned), every later `precheck()` returns `contained=False`.
- If termination or the empty check fails inside `finish()`, the job stays on the open-jobs list. `precheck()` re-checks it and fails closed until it is confirmed empty.
- The new tests fail on 73bdbef and pass after the change; no existing test is weakened.

**The change (`scripts/dev_workflow/containment.py`):**
- **New taint list:** a module-level `_TAINTED` list. `finish()` adds an entry whenever a process ran without a job. `precheck()` then returns `contained=False` and lists every such entry, even after later workers that were contained. It is never cleared within a driver run.
- **Failed jobs stay tracked:** `finish()` now adds the job to `_OPEN_JOBS` before it terminates and checks it. If `TerminateJobObject` or `QueryInformationJobObject` fails, the job is still re-checked by the next `precheck()`, which already fails closed on any error or on processes still running. The job handle is no longer lost. On that failure path `finish()` also runs the best-effort tree kill.
- **`lifecycle.py` unchanged:** `run_cmd` still ignores `finish()`'s result, but the next worker's `containment_pre` now picks up the state.

**Tests (`tests/dev_workflow/test_lifecycle_platform.py`):** I added a `terminate_fails` option to `FakeApi`. The fixture now resets `_TAINTED` with `raising=False`, so the file also runs on the old commit. Four new test cases:
- `test_r1_01_precheck_after_a_worker_without_a_job_is_not_contained`, run for job-not-created and job-not-assigned. It also checks the taint survives a later contained worker.
- `test_r1_01_precheck_after_a_failed_termination_is_not_contained`. It also checks that `precheck()` reports contained once a later termination empties the job.
- `test_r1_01_precheck_after_a_failed_empty_check_is_not_contained`.

**Verification:**
- **On 73bdbef:** I couldn't create a git worktree (permission denied), so I used a `git archive` export of 73bdbef with the new test file copied in. All 4 new tests failed at the `precheck` assertions; the 9 existing ones passed.
- **On this tree:** `tests/dev_workflow` gives 226 passed, 5 skipped. The 5 skips are the Windows-only tests, reported as PLATFORM-GATED; I reviewed that code by reading it.

**Docs:** `DEV_LIFECYCLE_2_PLAN_AND_ACCEPTANCE.md` (design section and DL2-AC4) and `URI_DEVELOPMENT_LIFECYCLE.md` now describe both behaviours.

**Not verified, and one limit:**
- **Real Windows:** I couldn't run real job objects here. The logic is proven only with the fake kernel32.
- **Taint scope:** the taint list, like the existing `_OPEN_JOBS`, lives only in the driver process's memory, so it covers one driver run. A process that ran without a job and outlives the driver process isn't seen by a later driver process. This was already true before this change, and doesn't affect the R1-01 verdict for a single run. Closing it would need state persisted on disk, which would be a separate design decision for you.
