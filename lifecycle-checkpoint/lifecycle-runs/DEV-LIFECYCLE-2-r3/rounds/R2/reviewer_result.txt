**New finding: R2-01 is fixed only for `OSError` (LOW, non-blocking)**

`run_cmd` (`lifecycle.py:675-683`) and `_run` (`lifecycle_providers.py:598-611`) catch only `TimeoutExpired` and `OSError` around `communicate()`. Any other exception skips `finish()`. On Windows the job is then never terminated, never added to the list of open jobs and never marked as running outside a job, so the next `precheck()` reports `contained=True` while the job's processes keep running.

- **How it happens:** with `text=True` and no encoding set, output the driver can't decode makes `communicate()` raise `UnicodeDecodeError` on POSIX. Reading CPython's Windows code, the same output there gives an `IndexError` instead; I couldn't run that on Windows.
- **Where it matters:** the regression proof runs `run_cmd` on test files the implementer wrote, inside `_commit_and_prove`. Its `except Exception` (`lifecycle.py:1222`) turns the error into REFUSED, and the driver keeps going. So the implementer's test can leave a process running in an unterminated job while a later worker starts with `contained=True`. That breaks DL2-AC4.
- **Linux is still safe:** the next orphan sweep catches the leftover process. On Windows, closing the job handle when the driver exits kills it, but only then.
- **Proof:** in `/tmp/uri_review_R2/cand/tests/dev_workflow/test_probe_decode.py`, with the fake kernel32, `run_cmd` and `run_worker` raise; the job shows `terminated=False`, nothing tracks it, and `precheck()` returns `contained=True`. A real Linux run of a child writing `b'\xff\xfe'` makes `run_cmd` raise `UnicodeDecodeError` before `finish()`. All 3 probe tests pass, which confirms the gap.
- **Docs:** `URI_DEVELOPMENT_LIFECYCLE.md` says every spawned worker or command goes through `finish()` "also when its communicate() fails". That is broader than the code.
- **Suggested fix:** call `finish()` from a `try/finally` (or catch `Exception`, then re-raise or record it), or decode with `errors="replace"`. Add a regression test for an exception that isn't an `OSError`.
