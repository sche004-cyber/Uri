I fixed R21-01 at its root cause in `uri_web/untrusted.py`. The new regression tests pass, and all 5154 tests in `tests/web` and `tests/assist` pass after the change.

**What caused it:** `_words` turns a run of marks with no base letter into a "word". The R20-01 repair then cleaned that word with `_bare`, which only removes marks whose Unicode name starts with "COMBINING". Script marks (Devanagari, Tibetan, Arabic, Thai, Telugu signs) stayed in, so three of them were read as the name of the link.

**The fix** (`_separator_word`, `uri_web/untrusted.py:580-585`): before `_bare` runs, any marks at the start of a word with no letter before them are now removed, whatever their name. A word made only of marks therefore comes out empty and counts as a separator again (the R19-01 rule), and the R20-01 handling of words that do have a base letter is unchanged.

I chose this over the suggested "skip marks inside `_words`" approach because that one would reopen the hole. The marks would become part of the gap between name and ending, which is then filtered down to plain prose. Since `shop` is not a core domain, the match would still be dropped.

**Tests:** new file `tests/web/test_w1_closure_r21_review_regressions.py`, with all non-ASCII characters written as `\u` escapes and no fixture files.

- It also checks that three pieces of ordinary text (Hindi + "shop", English, Thai + "shop") are not flagged as links.
