I fixed R42-01 at the cause named in the diagnosis, not with another per-token rule on top. A secret in a URL that is split across inline elements (`<b>`, `<span>`, `<em>`, `<a>`, `<i>`) is now masked in page text and headings, the same way the selection already masked it.

**In-page layer (`uri_assist/browser_extension/snapshot.js`)**
- **New grouping rule:** text nodes in the same block that sit next to each other inside inline elements now count as one "run". The new `newRun()` helper starts a new run only at:
  - a different block container,
  - a `<br>`,
  - a visible element that is not inline,
  - a whitespace-only text node between the two nodes.
- **Same group, no separator:** each run gets a single group id, so `finish()` and the Python `onscreen.join` join its pieces with nothing in between. A secret that crosses nodes is therefore masked as one token.
- **Where it applies:** page text (each run is masked as one chunk instead of node by node), headings (`visibleTextOf`), label pieces and contenteditable value pieces.

**Backstop in both layers** (`_split_url_parts` in `uri_assist/redact.py`, `splitUrlParts` in `snapshot.js`, the same rule in each)
- This runs after the existing per-token pass and errs on the side of masking when a URL has been cut by whitespace:
  - **Key with no value:** a secret-naming key with an empty value (`client_secret=`, or `client_secret` then `=`) masks the value in the next token.
  - **Split userinfo:** `scheme://user:` followed within two tokens by `…@` loses that userinfo.
- This covers the separators Python adds itself: `\n` between page-text groups and a space between heading groups.

**Trade-offs worth a look**
- **Over-masking in prose:** the backstop masks the next word after a bare secret-sounding key. `password = hunter2` becomes `password = [redacted]`, and so does `key = value`. I judged that acceptable.
- **Userinfo check catches some odd prose:** text like `https://example.com: … @home` can have the part up to the `@` removed.

Headings, labels and values used to join with a space; now inline-adjacent nodes join with nothing, so `<span>Save</span><span>All</span>` would read "SaveAll".
