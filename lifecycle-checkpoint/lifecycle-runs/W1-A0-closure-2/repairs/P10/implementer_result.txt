I repaired R26-01. Accented endings like `ćom`, `òrg`, `ṣhop`, `shóp` and `cásh` are now treated as top-level domains again, so text containing them is detected as a link and masked.

**Cause:** `normalise()` applies NFKC, which merges a letter and its accent into one precomposed character (`c` + `́` becomes `ć`). `_tld_match` only removed separate accent marks, so a merged one survived and the ending no longer matched the domain list.

**Fix:** a single change in `uri_web/untrusted.py`, inside `_tld_match`. It now splits the ending into base letters and accent marks (NFD), removes the marks, and recombines what is left (NFC) before checking the domain list. This fallback runs only when the plain spelling doesn't match, so endings that are already listed are unaffected. The function's docstring ("combining marks are ignored") is now accurate. I did not take the suggested second step of also running `_ending_spans` on the skeleton text. It wasn't needed to close any of the reported cases, and it could start flagging look-alike letters in ordinary text in other scripts.
