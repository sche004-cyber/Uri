## Diagnosis: R5-01 (the R1-01 link-bypass class), HEAD 806dcd12

**Short version:** the exact strings in R5-01 are fixed at HEAD. The class of bug is not. The detector only recognises the separators it lists, and every repair added one more shape to that list.

**What I checked** (all read-only; probes are in `/tmp/d5/p1.py`, `p2.py` and `p3.py`):
- **R5-01's own cases now pass.** `_refunds-portal.com_`, `refunds.com-`, `__refunds.cash__` and `_refundsportal.xn--p1ai_` all return True from `has_link_or_contact` and get masked. Commit 29771992 fixed those.
- **The same bug still gets through with other separators.** I used the reviewer's sentence ("Claim your energy rebate refund at X before the deadline."). `has_link_or_contact` returns False for all of these:
  - `refunds..com/claim` and `refunds…com`
  - punctuation from other scripts: `refunds-portal،com` (U+060C), `।` (U+0964), `։` (U+0589), `۔` (U+06D4), `⸱` (U+2E31), `܁` (U+0701), `᛫` (U+16EB), `።` (U+1362), `་` (U+0F0B)
  - `꞉` (U+A789) and `˙` (U+02D9)
  - `refunds-portal,com/claim`, `refunds-portal:com`, `refunds-portal d0t com`, `refunds-portal_dot_com`, `refunds-portal-dot-com`, `refunds-portal.c om`
- **These pass every later check too.** For each one, `verify()` keeps the Brain's sentence unquoted and `extractive()` picks it. `build_surface` then shows the link and `require_valid` accepts the surface. I confirmed that last step for `..`, `،`, `।`, `d0t`, `,`, `:`, `_dot_` and `⸱`.
- **A smaller gap:** for `refunds-portal . Com` and `refunds-portal. Com/claim`, the sentence splitter (`_SENT`, `uri_web/evaluate.py:38`) cuts the link in two. `verify` then keeps `'Com before the deadline .'` and `extractive` keeps `'… at refunds-portal .'`. Neither half is a link alone, but shown together they rebuild one. D13 already records this as a known limit.

**Why every repair missed it:** each one made the list of accepted shapes longer, and each was checked only against the strings the reviewer reported.
- ca622bc0 added `[.]`, `(.)` and `[dot]`.
- f3700643 added three Unicode full stops.
- 462be42c added spaced brackets.
- f5a5b8ec added the `xn--` top-level-label form.
- 29771992 fixed the `_` and `-` boundary.
- 806dcd12 (D13) added a 14-character dot list (`_DOTCH`), which still leaves out most dot-like and separator marks.

The R5 regression test (`tests/web/test_w1_closure_r5_review_regressions.py:23`) lists fixed strings, so nothing in the test suite ever forced a general rule. D13 asked to "mask any dot-joined word", but it was built as a list rather than a rule.

**Proposed fix:**
1. In `untrusted.py`, inside each whitespace-separated token (after NFKC and dropping invisible characters, and on the skeleton too), treat any run of separators as a dot. A separator is any character whose Unicode category starts with P or S, or is Sk, other than a single word-internal `-`, `'` or `’`, and other than `/`. The same goes for `dot`/`d0t` in any wrapper or spacing (`_dot_`, `-dot-`, `{dot}`). The match counts when the next label is 2–63 letters or an ACE label.
2. Keep the existing exceptions, which only ever cost precision: a full stop, comma or colon followed by a space and then a capitalised word, `rose.The`, the CJK `。` break, and abbreviations.
3. Run `has_link_or_contact` on the unsplit source paragraph as well as on each sentence. A sentence next to one that was dropped as `LINK_OR_CONTACT` should be quoted or dropped too, which closes the `. Com` split case.
4. Change the tests from string lists to generated ones: every character in categories Po, Pd, Ps, Pe, Sk and Sm placed between `refunds-portal` and `com`, run through `has_link_or_contact`, `verify`, `extractive`, `build_surface` and `require_valid`.
