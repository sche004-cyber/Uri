I fixed R4-01. If `scripts/ws_frozen_check.py` in the main checkout is relaxed between runs, the run now stops BLOCKED (CONFIG), even when the config file hasn't changed by a single byte. Nothing is committed.

**The fix** (`scripts/dev_workflow/lifecycle.py`):
- A new `policy_sha256(cfg)` hashes the policy actually in effect when the run happens, including the protected list read from `ws_frozen_check`.
- PLAN, CONFIG_CHANGED and OWNER_UNBLOCK events now record that hash next to the config file hash.
- `config_binding()` reads the bound pair (config hash, policy hash) from the event chain only, never from `state.json`. The policy hash comes from the `policy` dict the event already records, so existing PLAN events need no migration.
- `run()` records CONFIG_CHANGED and blocks if either hash differs. The block clears only after an owner unblock that recorded the same pair.

**One wrong turn along the way:** my first version stored the policy hash once, when the config was loaded. That broke 15 existing tests, because they edit `cfg` in memory after loading it, so the stored hash went stale. Computing the hash live on each run fixed it, and it is also the more accurate check.
