**R3-01: a redirected HEAD let the revert move another branch**

- **After a repair:** a changed HEAD branch is now TAMPER.
- **On revert:** `_restore` sets the candidate branch to the pre-repair commit, points HEAD back at it, then runs `reset --hard` and `clean`. It counts the worktree as restored only if HEAD's branch, HEAD and the branch tip all match. So `reset --hard` can only move the candidate branch.
- The review integrity snapshot now includes the branch HEAD names.

**R3-02: a failed baseline gate result was cached forever**
- A cached baseline result is reused only if it is `COMPLETED_WITH_RESULT`. Otherwise the gate re-runs on the next qualification, and each attempt is recorded as its own BASELINE_GATE event.

**R3-03: a moved candidate was never re-audited**
- When a block would resume at VERIFYING but the current candidate has no independent ACCEPT, it now resumes at AUDITING.
