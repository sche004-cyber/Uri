R5-01 is repaired. In merge mode the driver now checks git control state again after the combined gates run and before the push. If anything changed, it refuses the push and blocks as TAMPER. It checks once more after the push, so a change during the push can't count as integrated.

**What changed**
- **`scripts/dev_workflow/lifecycle.py` (in `integrate()`)**:
  - **Before the push (merge mode only):** after the gates run on the merge result, the driver re-runs `control_drift`. That check covers the user-level `~/.gitconfig` and other config files, the repo's hooks, config and info files, and `refs/replace`. On any drift it records the integration status as `REFUSED_TAMPER` and blocks as `TAMPER`, without pushing.
  - **After the push (every mode):** `control_drift` runs again after the push and its `ls-remote` check. If anything changed, the status becomes `UNVERIFIED_TAMPER` and the run blocks as `TAMPER` instead of reaching COMPLETE.
- **`tests/dev_workflow/test_lifecycle.py`**:
  - **New test:** `test_r5_01_combined_gate_writing_global_insteadof_cannot_fake_a_merge_integration` reproduces the reviewer's probe. The candidate's `tests/conftest.py` adds an `insteadOf` line to `$HOME/.gitconfig`, but only when running in the `integration` worktree. The test expects BLOCKED with `REFUSED_TAMPER`, and checks that neither the real nor the fake remote moved from the base commit.
  - **Fixture fix:** the `user_home` fixture now also points `HOME` at the throwaway directory for gate commands. Gate commands get their environment from `NOBYTECODE`, a copy of `os.environ` taken at import, so before this fix a gate test could write to the real `~/.gitconfig`.

**Verification**
- **Original code:** with the original `lifecycle.py` swapped in, the new test fails. The run reaches COMPLETE and pushes to the fake remote.
- **With the fix:** the new test passes.
