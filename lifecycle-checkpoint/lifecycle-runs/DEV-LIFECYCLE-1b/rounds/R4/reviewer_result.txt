**New finding R4-01 (MEDIUM, blocking): user-level git config is not checked.** `git_control_digest` only hashes the repository's own `config`, `hooks/` and `info/`. A worker runs as the same user and can append to `~/.gitconfig` with plain shell. The `Bash(git config*)` deny rule doesn't stop that, and `control_state` doesn't change. I reproduced two effects:
- **False "INTEGRATED":** a `url.<fake>.insteadOf=<origin>` entry sends both the driver's `push` and its `ls-remote` check to a substitute remote. The push exits 0, the check matches, and the real remote is never updated. The run would end COMPLETE.
- **Reviewer and gates see different code than the commit:** a global smudge filter plus a committed `.gitattributes` made the audit checkout show `DEFECT = False` while the committed file says `DEFECT = True`. The worktree still read as clean to the integrity check.

The fix is to include the global/system config and the default attributes file in the control digest, or run the driver's git with `GIT_CONFIG_GLOBAL`/`GIT_CONFIG_NOSYSTEM`. The second would also drop any credential helper set in the global config, so pushing may need its own handling.

**Non-blocking (LOW):**
- **R4-02:** a REJECT whose finding has a non-string title crashes the run with an uncaught `AttributeError` in `_fingerprint`. It never becomes an ACCEPT; the stage stays AUDITING and the next run starts a fresh review.
- **R4-03:** `URI_DEVELOPMENT_LIFECYCLE.md:85` still calls `max_rounds` "the hard bound". The code now refuses `limits.max_rounds`; the cap is `continuation.budget.max_rounds`.

**Tests:** `pytest tests/dev_workflow` gave 165 passed. No protected path changed in the range, and the checkout is still clean at `475533a`.

**Not checked:** live `claude` worker runs, Flutter gates, a real GPU lease, pushing to a real hosted remote, and Windows. Separately, a worker child that detaches from its process group (`setsid`) can rewrite the whole state directory into a consistent chain. The docs already state this as a limitation.
