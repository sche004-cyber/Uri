**R1-01 (MEDIUM, blocking, test): the conftest placeholders leak into later tests.**
- `tests/graphify/conftest.py` imports `uri_core.app.server` while the placeholders are installed. Afterwards it removes only the `google*` entries from `sys.modules`.
- `uri_core.app.server` and `uri_core.services.*` stay imported with Mock objects in place of the Google client code. For example, a probe test run after `tests/graphify` sees `uri_core.services.gmail_service.build` as a MagicMock.
- Reproduction:
  - `pytest tests/test_m31_model_brain_ux.py` alone: 1 collection error.
  - `pytest tests/graphify tests/test_m31_model_brain_ux.py`: 25 passed.
  - `test_decision_engine.py` behaves the same: error alone, 60 passed together with `tests/graphify`.
- `tests/graphify` sorts before `tests/test_*`, so this happens in a plain `pytest tests` run too. It contradicts the conftest's own docstring and can hide real failures in the baseline comparison.
- The fake credential secret is also set with a module-level `setdefault` and stays set for the whole session.

**R1-02 (MEDIUM, blocking, code): lookups now edit the view's records without a lock.**
- Every `get`, `list_all` and `relevant_subset` now deletes and rebuilds the memory records in place. Before this change, lookups only read.
- `/ask` is a sync endpoint, so FastAPI runs it in its thread pool. Two Brain turns for the same user, or any no-login turns (they all share one view), can therefore overlap.
- Probe (300 memories, `sys.setswitchinterval(1e-6)`): two threads calling `relevant_subset` raise `KeyError: 'memory:…'` from `_sync_memory`. That happens outside `relevant_subset`'s own try, so "never raises" fails.
- `list_all` also raises `RuntimeError: dictionary changed size during iteration`.
- The capability refresh's `graphify_refresh(scope="capabilities")` raised the same RuntimeError about 1,470 times in that run. `external_lifecycle_lock` doesn't cover Brain-turn lookups. When that refresh raises, `refresh_user_external_lifecycle` exits before it swaps in the new `multi_action_dispatch`, so a capability change isn't published.
- `decision_engine` catches the `relevant_subset` error, so in a Brain turn the effect is a dropped hint for that turn rather than a crash.
- Suggested fix: build the merged record dict privately and swap it in under a per-view lock that the capability/service refresh also takes.

**Low notes, not findings:**
- Cost is one JSON file read per lookup, which is the limitation the plan already documents.
- Records are copied one level deep. Inner record dicts are shared with the shared index, as they were at baseline.
