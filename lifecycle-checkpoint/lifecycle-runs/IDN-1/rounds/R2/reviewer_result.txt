**R2-01 (LOW, non-blocking): some refusals don't say why**
A few unusual address forms are still refused and never contacted, but they get a different refusal code, so they aren't counted and no note is shown:
- A percent-encoded host such as `http://%D1%80aypal.com/` is refused as `HOST_INVALID`, whether it comes in as a user URL, search hit or redirect. Browsers decode this to `раураl.com`.
- A redirect to a full-width host such as `http://ｐａｙｐａｌ.com/` ends as `UNREACHABLE`, because httpx rejects the redirect URL before `check_url` runs.

Real sites are unlikely to use these forms. The suggested fix is to return `HOST_NON_ENGLISH` when a host contains `%` that decodes to a non-ASCII name, and to read the raw `Location` header in `safe_fetch.py` so redirects go through `check_url`.
