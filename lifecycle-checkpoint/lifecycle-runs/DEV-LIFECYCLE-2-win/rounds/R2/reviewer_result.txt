**Blocking finding (R2-01, medium).** The design says any containment API failure must fail closed, and that "before each worker, every earlier job must still show 0". `precheck()` only looks at jobs that `finish()` stored in `_OPEN_JOBS`, and two failure paths never store anything there:
- **No job.** If job creation or assignment fails for a gate, test or implementer, `finish()` uses `taskkill /T` and returns `contained=False`. A detached grandchild whose parent has already exited is not in that tree, so it survives.
- **Termination fails.** If `TerminateJobObject` fails, the job is neither stored nor closed, so the worker can keep running.

In both cases the next reviewer's `precheck()` returns `contained=True`, and `is_independent()` accepts the round. That is the R8-01 attack (a leftover process running alongside the reviewer) reopened on Windows. `run_cmd` also ignores the result of `finish()` for gates. I reproduced both cases with a fake kernel32 (`/tmp/uri_review_R2/probe_precheck.py`, `probe_terminate.py`): `finish` gave `contained=False`, then `precheck` gave `{'contained': True}`. Triggering it needs a kernel32 failure, so it is rare, but it breaks a stated fail-closed criterion. The suggested fix needs no protected path.
