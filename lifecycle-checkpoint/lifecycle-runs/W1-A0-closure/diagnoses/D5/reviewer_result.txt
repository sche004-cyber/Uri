I found the root cause. The hidden-text filter in `snapshot.js` works from a list of known ways to hide text and keeps everything it can't prove is hidden. Each repair added the tricks the last reviewer named, so the next review found new ones. The two existing regression tests (R10/R11, 4 tests) still pass, because they only cover the tricks they were written for.

**Reproduced at d5a9b41.** I loaded a page in real Chromium, pressed Ctrl+A and ran `snapshot.js` (probe in `/tmp/diag_D5/page.html` and `run.cjs`). The payloads hidden by `filter:opacity(0)`, `opacity:0.01`, `-webkit-text-fill-color:transparent`, the four `clip-path` insets, `circle(0)`, `polygon(0 0,0 0,0 0)`, a transparent `mask-image` and closed `<details>` content all came back in both `text` and `selection`. `redactions` was only `{"hidden_text":2}`. Text in plain white on the white page also got through, which the docs list as a known gap. `transform:scale(0.01)` was the one case dropped, and only because its rect fell below 2px.

**Why each check misses:**
- **Opacity:** `checkVisibility({opacityProperty:true})` (`snapshot.js:57-58`) only catches an element's own `opacity:0`. It ignores `filter:opacity()`, near-zero opacity and opacity multiplied down through ancestors.
- **Clip-path:** the test `/inset\(\s*(50%|100%)/` appears twice (`snapshot.js:63` and `:87`). It only matches when the first inset value is exactly 50% or 100%, so it misses other sides, other percentages, circles, polygons and ellipses.
- **Text colour:** `textVisible` checks only `color` (`snapshot.js:126`), never `-webkit-text-fill-color`.
- **Masks:** nothing checks `mask-image` or `-webkit-mask-image`.
- **`<details>`:** closed content still returns layout boxes, so the rect checks at `snapshot.js:59-60` and `:132-135` let it through.
- **Docs:** `docs/assist/03_PERMISSION_AND_DATA_FLOW.md:77` says opacity, transparent text colour and clip-path inset are covered, and its "Not covered" list doesn't mention any of these cases.

**Why the repairs missed it:**
- **2de591e (R10-01)** only connected the selection to the existing `visible()` check. The check itself was unchanged.
- **d5a9b41 (R11-01)** added checks for exactly the five tricks the R11 reviewer listed (screen-reader-only clip, overflow clipping, text-indent, covering overlays, transparent colour). It reused the narrow clip-path test, added no opacity or mask handling, and widened the docs claim. Its test page contains only those R11 patterns, so it passes no matter what new tricks a reviewer tries.
