**What changed**
- **R9-01 (selected text in fields):** `snapshot.js` now rebuilds the selection only from the page's own text inside the selected range. Field contents are never included, and the page reports only that a field selection exists (`selection_withheld`). In real Chromium the old script leaked `482913`, `417`, the e-mail, the textarea and the contenteditable; the new one leaks none of them. Python accepts a selection only when it is marked as page text and contains no withheld value. The Brain then sees "the user has selected text inside a form field", never the text itself.
- **R9-03 (`has_value` dropped):** `normalise()` now keeps the page's `has_value` and its decision to withhold a field. If it isn't known whether a field is filled, a screenshot is still refused. The "required and empty" warning now fires only when the field is known to be empty.
- **R9-04 (answers after revoke):** grant, pause and revoke blank stored answers. `assist_ask_status` returns an answer only while the grant that produced it is unchanged. Otherwise it reports CANCELLED with no answer and no page summary. I blanked rather than deleted because existing tests expect a CANCELLED status after revoke.
- **R9-05 (UI keeps old data):** grant, pause, resume, Stop and a worker change now clear findings, the last observation, the answer and the ask id. A check or ask reply sent before one of those events is dropped.
- **R9-02 (numbers in the Brain's words):** two layers.
  - Ordinals built on number words (e.g. "eleventh", "thousandth"), Unicode number and currency characters, and Roman numerals now count as quantities.
  - Not depending on any list: if a Brain sentence adds any word beyond a small set of function words to its supporting source sentence, the source sentence is quoted instead, or the claim is dropped.
  - I did not use the suggested plain `-th/-st/-nd/-rd` rule: it matches "and", "board" and "most", quoted almost every sentence, and broke two existing tests.
- **R9-06 (DNS outside the timeout):** the lookup runs on a helper thread and waits at most the smaller of the remaining budget and the connect timeout, while checking cancel. The result is TIMED_OUT or CANCELLED. The page lookup isn't started once robots.txt has used the budget. A blocked system lookup can't be killed, so its thread is left running in the background; I noted this in the doc.
