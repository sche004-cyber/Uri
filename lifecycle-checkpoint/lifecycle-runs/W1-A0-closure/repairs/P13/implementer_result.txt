I fixed R12-01. The filter now drops text unless it is actually shown, instead of only catching a fixed list of known hiding tricks. Earlier repairs patched one trick at a time. This change works out every paint effect from the whole ancestor chain, and anything it can't evaluate is treated as hidden.

**What changed in `uri_assist/browser_extension/snapshot.js`**

For each text node, the existing walk up its ancestors (`clipBoxOf`) now also checks paint effects, applied regardless of positioning. It also walks up to and including `<html>`.
- **Opacity:** the product of `opacity` and `filter: opacity()` across all ancestors. Below 0.1 counts as hidden. An SVG `filter: url()` counts as hidden.
- **Text colour:** the check uses the colour actually painted (`-webkit-text-fill-color`, otherwise `color`). If its alpha times the opacity above is below 0.1, the text is hidden. `alpha()` now also reads the alpha in `oklch(… / a)` and similar colour formats.
- **Masks:** a `mask-image` hides the text unless one layer is a gradient with a stop of alpha 0.1 or more that covers the box. `url()` or image masks, luminance mode, compositing other than `add`, and zero-size masks count as hidden.
- **`clip-path`:** read as real geometry: all four inset sides (including the 3-value and `calc()` forms Chromium produces), circle, ellipse, and polygon (bounding box plus area). `path()`, `url()` and anything it can't parse count as hidden. This replaces the old leading-`50%`/`100%` inset regex.
- **Closed `<details>`:** content is dropped unless it sits inside that element's `<summary>`.

Page text, headings and the selection all go through the same per-text-node check. `visible()`, which is also used for form fields and the black-out boxes over sensitive fields, is unchanged. Making it stricter could drop the black-out box for a sensitive field that is really on screen.

**Tests**
- **New:** `tests/assist/test_a0_r12_review_regressions.py` is self-contained, with the page and Node runner embedded and written to `tmp_path`. It fails rather than skips if node is missing.
  - **Hidden cases:** 18 payloads. They cover every technique in the finding, plus opacity multiplied through two ancestors, `rgba(…, 0.02)` text, `filter` opacity combinations, ellipse, a zero-area polygon, `path()`, and a `<p>` inside closed details.
  - **Kept controls:** 11 that must survive: opacity 0.5, `inset(10%)`, open details, summary text, a gradient mask, `color: transparent` with a visible fill colour, `circle(50%)`, `filter: opacity(0.6)`, among others.
  - **What it checks:** text, selection and headings after both Ctrl+A and a full-range selection, and the FakeClient Brain request through `mk`/`grant`/`ask_and_wait`.
- **Before the fix:** I ran both tests on the unmodified `snapshot.js` and both failed. The payloads were in the selection and in the Brain request.
- **After the fix:** the R10, R11 and R12 tests pass (6 passed), and the full `tests/assist` and `tests/web` run gives 2633 passed. A separate check in real Chromium confirmed that a fade-out gradient mask, a padding-box inset, `xywh()` and bold summary text are kept, while `url()` masks, tiny masks, SVG filters, `oklch` alpha 0 and nested closed details are dropped.

**Docs:** the threat-table row in `docs/assist/03_PERMISSION_AND_DATA_FLOW.md` now lists exactly what the code covers. Its "Not covered" list adds low-contrast text (including `filter` brightness/contrast and blend modes), transforms that leave glyphs 2px tall or more, and gradient masks that are opaque somewhere but transparent over the text.

**Known limits**
- Treating unparseable shapes and masks as hidden may drop text from real pages that use `clip-path: path()` or image masks. That trade-off is deliberate for security.
- I did not run `graphify update .`, because it writes to `graphify-out/`, which is outside the paths I was allowed to change.
