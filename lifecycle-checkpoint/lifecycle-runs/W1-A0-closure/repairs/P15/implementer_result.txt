**How the check works now**
- **Snapshot (`snapshot.js`):** every piece of text sent to URI names the "units" it was built from (one range of one text node). It carries no extra text content, only counts and the node's length.
- **Probe (new `uri_assist/browser_extension/probe.js`):** after the snapshot, the adapter takes in-memory screenshots:
  - the page as it is;
  - for each group of units, one with only that group's letters made transparent and two with them painted in random probe colours, using the browser's highlight feature;
  - the page as it is again.

  The DOM, `page.content()` and the user's selection are unchanged afterwards, and the tests check that.
- **Verifier (`onscreen.py`):** a unit is kept only if all of these hold:
  - its own pixels take its probe colour in both tints, consistently;
  - its own colour differs from what is behind it;
  - every part of its box shows its letters;
  - the page stayed still during the probe.

  Hidden text over visible text, borders or patterns therefore changes nothing and is dropped. So is white-on-white, masked, below-background or covered text, and text under a flickering background. Units that touch are probed separately, and a page that changed between snapshot and probe is rejected. With no valid probe, no page text is sent.
- **Wiring:** `perception.py` now calls `adapter.probe()` instead of taking one screenshot. bridge.py only got a comment update; the prompt labels stay "pixel-checked".

**Tests**
- New `tests/assist/test_a0_r13_differential_render.py` is self-contained (page and Playwright driver embedded). It covers, in real Chromium with and without Ctrl+A:
  - the five overlap payloads from the diagnosis and the reviewer's R13 payloads;
  - new overlap variants (transparent, white, opacity 0 and clip-path text over visible text, text under a border, a partly clipped node, a flickering background);
  - the R11/R12 payloads;
  - visible text right under the payloads, which still reaches the Brain.

  It also has unit tests on synthetic probes. It passed 6 of 6 repeated runs; the probe colours are random each run.
- Existing tests were moved to the new probe contract with the same assertions: R10/R11/R12 runners now run the probe, and `mk()`/`FakeAdapter` take a probe. In the D10 test file I rewrote its synthetic tests of the old edge-counting check against the new probe, keeping each test's intent.

**Docs:** the "hidden text that overlaps other ink passes" limit is removed from docs/03 and A0_QUALIFICATION. It was an open bypass, not a limit, and I recorded that as a correction note, keeping the history. Both docs now state the remaining limits.

**What you should know**
- **Visible text that is no longer sent:** SVG `<text>` is never kept now, because the highlight doesn't repaint it. SVGOK-OK-9 moved from "kept" to "not verifiable" in the D10 test. Very faint, very thin, widely spaced, animated, partly clipped or under-about-5px text is also dropped.
- **Pages whose scripts react to the probe (not fixed):** a script can notice the probe (the selection change, the highlight registry) and show text only while it runs. Pausing page scripts during the probe closes this. I tested the browser's script-disable switch (Chrome DevTools Protocol): it freezes timers and animation callbacks, but it also permanently stopped the page's own animation loop. That trade-off is your call.
- **Not verified:**
  - The extension channel doesn't exist in A0. The extension version must inject the probe rules in a way the page can't read (`chrome.scripting.insertCSS`, user origin) and run probe.js in its isolated world. The tests use a style sheet the page could read.
  - Only headless Chromium at device pixel ratio 1 was tested, not Windows or other pixel ratios.
- **Cost:** each ask now takes 2 screenshots plus 3 per group (2 groups on normal pages). Checking costs about 1.4 s for a viewport full of text.
- **Fixed along the way:** my first version of the unit fingerprint hashed raw text, which could carry secrets. It is now the text node's length.
