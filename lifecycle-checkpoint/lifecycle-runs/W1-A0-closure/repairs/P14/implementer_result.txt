**Field labels were not checked at all** (part 1 of the diagnosis):
- **In the page (`snapshot.js`):** a field's label is now built only from visible text inside its `<label for>`, its surrounding `<label>` and its `aria-labelledby` targets. Text inside other fields is skipped. The label is sent with its on-screen positions so the screenshot check can test it, like headings. A field that isn't shown gets no label.
- **Attributes:** `aria-label`, `name`, `id`, `placeholder` and the old `innerText` label are now used only for the in-page "is this sensitive?" test. They are never sent as a label.
- **In URI (`perception.py`):** a field's label for the Brain (`shown_label`) comes only from label text the screenshot shows drawn.
- **In the Brain request (`bridge.py`):** `_context_block` no longer falls back to `name` or `id`. A field without a drawn label is named neutrally, e.g. "text field 3".
- **Unchanged:** the local form checks (`assist_check`) still use the full label. Their results go to the user, not the Brain.

**The screenshot check wasn't tied to the text** (part 2):
- **In URI (`onscreen.untangle`):** after the screenshot check, two kept pieces whose text differs and whose boxes overlap substantially are both dropped. This applies across page text, selection, headings and labels, and each drop is counted as `overlapping_text`. This rule alone is what removes the `pointer-events:none` variants: with it switched off, two of the test payloads still reached the Brain.
- **In the page, opaque layers:** `covered()` now uses the browser's painting order at the text's position (`elementsFromPoint`). An opaque layer painted above the text now hides it even when that layer is the text's own ancestor (the negative z-index case).
- **In the page, background colour:** text drawn in the same colour as the opaque background directly beneath it is now dropped everywhere. Before, this rule only applied to selected text.

**The R13-01 techniques** are now also removed in the page:
- SVG text uses its `fill` (none, transparent or a `url()` fill count as not drawn) times `fill-opacity`, or its stroke if one is drawn.
- `-webkit-mask-box-image` / `mask-border` counts as masked.

**One existing test changed.** In `test_a0_d10_pixel_checked_text.py`, `PIXEL_ONLY` asserted that the R13 payloads get past the in-page rules. That is no longer true, so it now lists only BLUR, PEN and BELOWFOLD. A new assertion requires the R13 payloads to be removed in the page, and the `no_ink` minimum dropped from 9 to 2 because fewer pieces now reach the screenshot check. Every check on what reaches the Brain is unchanged.

**Docs.** `docs/assist/03` §4 and `A0_QUALIFICATION` (the A0-AC8 row, L-A0-5 and a new evidence row) now describe the field-label channel and the overlap rule. Each has a correction note recording that at `fcfb465` field labels were an unchecked channel.

**Still not covered** (written into the docs): hidden text placed over drawn ink that isn't page text, such as borders, images or canvas, still passes unless an in-page rule catches it. The "pixel-checked" wording in the Brain request is kept, with that limit documented. The thresholds were tuned only on headless Chromium at pixel ratio 1; Windows rendering and other pixel ratios are not verified.
